# Staging `.env` — recommended values

No secrets in this file. This documents what `application/.env` should
contain on staging (`staging.kencomanufactur.co.id`) — it is created **once,
manually, directly on the server**, never committed, never generated by any
script in this repo.

```env
APP_NAME="PT. Kenco Manufactur Indonesia"
APP_ENV=staging
APP_KEY=                          # generate with artisan key:generate, see below — never copy from local/production
APP_DEBUG=false
APP_URL=https://staging.kencomanufactur.co.id

APP_LOCALE=en
APP_FALLBACK_LOCALE=en
APP_FAKER_LOCALE=en_US

LOG_CHANNEL=stack
LOG_STACK=single
LOG_LEVEL=warning

DB_CONNECTION=mysql
DB_HOST=<Hostinger-provided host, typically localhost>
DB_PORT=3306
DB_DATABASE=<staging-specific database — never reuse the future production DB>
DB_USERNAME=<staging-specific user>
DB_PASSWORD=<real secret, set directly on the server>

SESSION_DRIVER=database
SESSION_LIFETIME=120
SESSION_SECURE_COOKIE=true          # staging is HTTPS-only once SSL is active
SESSION_ENCRYPT=false

CACHE_STORE=database
QUEUE_CONNECTION=sync               # no queue workload exists yet — see PHASE-11A1 audit

FILESYSTEM_DISK=local

MAIL_MAILER=log                     # IMPORTANT — see below
MAIL_FROM_ADDRESS="noreply@kencomanufactur.co.id"
MAIL_FROM_NAME="${APP_NAME}"
```

## Why `MAIL_MAILER=log` on staging

Real production SMTP is not configured yet (see
`docs/PHASE-11A1-HOSTING-AUDIT.md`'s mail recommendation — this app doesn't
even send any email today, there's nothing implemented that would trigger a
send). Setting `MAIL_MAILER=log` means anything that *does* eventually call
`Mail::` writes to `storage/logs/laravel.log` instead of actually
attempting to send — this guarantees staging can never accidentally email a
real person while it's being used for testing. Do not set a real SMTP
mailer on staging until there's an explicit reason to test actual mail
delivery, and even then, test with addresses you control.

## `APP_KEY` — first-time setup

Generate it fresh, on staging, after `.env` exists with everything else
filled in:

```bash
/opt/alt/php83/usr/bin/php /home/u518638233/domains/staging.kencomanufactur.co.id/application/artisan key:generate
```

Never copy `APP_KEY` from local development or from a future production
`.env` — each environment must have its own, generated once and left alone
(rotating it invalidates every existing session and any data encrypted with
the old key).

## `PUBLIC_PATH` — not needed

The split `application/` + `public_html/` layout does **not** require a
`PUBLIC_PATH` override or any other `bootstrap/app.php` change. See
`docs/PHASE-11A2-STAGING-DEPLOYMENT.md`'s "Public path audit" section for
why — in short: the one thing that reads `public_path()` at runtime is
Vite's manifest lookup, and it resolves correctly against
`application/public/` (where the build output originally lands before being
mirrored into `public_html/` for the browser to fetch directly), so no
override is required, and none was added.
